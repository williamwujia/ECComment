# 决策记录

只记录会约束后续工作的决定。若决定被推翻，不删除旧记录；新增一条并标注被替代关系。

## D-001：项目记忆分为三层

- 日期：2026-08-13
- 状态：已采用
- 背景：更新和调整数量增加，仅依赖聊天、提交信息或散落说明会导致前后口径不一致。
- 决定：
  - `PROJECT_STATUS.md` 保存当前真相、进行中事项、风险和下一步；
  - `CHANGELOG.md` 保存面向使用者的历史变化；
  - 本文件保存影响后续工作的原因与取舍；
  - `AGENTS.md` 强制每次实现同步维护上述记录。
- 原因：当前状态与历史流水的更新频率、读者和用途不同，混在一份文档里会迅速膨胀并失效。
- 替代方案：只依赖 Git 提交；未采用，因为提交说明通常不能表达产品口径、待处理项和未提交工作。
- 影响：完成定义从“代码可运行”扩展为“代码、测试、状态和变更记录一致”。

## D-002：用评论增速表达销售活跃度，不换算销量

- 日期：2026-08-13
- 状态：已替代（被 D-003 替代）
- 背景：持续追踪已经能识别相邻快照间的新增评论，品牌浏览者希望据此了解商品销售进展，但项目没有真实订单数据，也没有经过标定的评论率。
- 决定：将首个快照视为评论基线；从第二个快照起，以首次发现的新增评论除以实际更新间隔，展示“评论增速”和销售活跃度趋势。至少有两个可比较区间时，日均增速变化达到 ±20% 才标记为上升或回落。界面始终声明该指标不等于真实销量。
- 原因：评论增长能提供方向性的销售活跃度信号，但评论率会受平台、品类、促评方式和延迟影响，直接换算订单数会制造不可靠的精度；按天归一化可以减少更新间隔不同造成的误判。
- 替代方案：使用固定“每 N 单产生一条评论”的系数估算销量；未采用，因为目前没有可信、稳定且分平台分品类的标定数据。
- 影响：后续所有销售进展展示都应保留代理指标说明；只有获得真实销量或可信标定数据后，才能另行增加销量区间估算。

## D-003：按评论日期和 5% 评论率估算月销量

- 日期：2026-08-13
- 状态：已采用
- 背景：销售进展的目标是利用评论自带日期比较不同月份的销量变化，并采用“5% 的客户会评论”这一明确业务假设，而不是比较抓取快照之间的增量。
- 决定：仅将主评论按自身日期归入自然月，按“估算销量 = 月评论数 ÷ 5%”计算商品月销量，并展示相邻有数据月份的环比变化。追评、问答及缺少有效日期的评论不进入销量估算；页面必须展示日期覆盖率和假设说明。
- 原因：评论日期更接近购买发生的时间分布；固定评论率可以把评论数量映射为易理解的销量尺度。排除追评可避免同一订单因多次发言重复计数。
- 替代方案：按快照抓取时间计算新增评论增速；未采用，因为抓取时间取决于维护节奏，不能准确代表评论或销售发生时间。
- 影响：5% 是业务假设而非观测事实，估算结果必须以“约”“估算”标识；未来如调整评论率，应作为明确的产品口径变更记录。

## D-004：启动器统一使用独立端口探测脚本

- 日期：2026-08-13
- 状态：已采用
- 背景：中文批处理启动器将复杂的 PowerShell 端口探测嵌入 `for /f` 命令替换；当 8501 被占用时，`cmd.exe` 的引号解析会导致探测失败并误报没有可用端口。
- 决定：四个 Windows 启动入口统一调用仓库根目录的 `find_available_tcp_port.ps1`，从起始端口递增探测并输出首个可用端口；批处理入口使用 `-File` 调用并开启 `-ExecutionPolicy Bypass`。
- 原因：独立脚本可直接测试，避免在批处理命令替换中重复嵌套 PowerShell 语法，并保持各入口行为一致。
- 替代方案：继续在每个启动器内复制探测函数；未采用，因为容易产生修复不同步和批处理转义问题。
- 影响：启动脚本依赖新增的端口探测脚本；端口探测回归测试覆盖“起始端口被占用时选择下一个端口”。

## D-006：综合采集助手与京东专用采集器并行保留

- 日期：2026-08-24
- 状态：已采用
- 背景：淘宝、天猫和京东需要统一批量更新，但现有京东专用采集器已经过真实页面验证，仍需要作为独立兜底能力。
- 决定：新增独立 `ecommerce_review_assistant/` Chrome 扩展，使用独立名称、目录、存储键和下载文件名；不改造或替换 `chrome_extension/`。两者输出都使用服务器现有结构化评论 CSV 导入契约。
- 原因：独立扩展可减少三平台改动对已验证京东流程的回归风险，同时复用服务器预览、去重、分析、备份和写入能力，避免产生第二套数据链路。
- 替代方案：直接把现有京东扩展原地重构为三平台版本；未采用，因为平台选择器变化会同时破坏唯一的京东采集入口。
- 影响：后续综合助手和京东专用扩展必须使用不同的状态命名空间；综合助手的淘宝、天猫选择器需经真实登录页面验证后才能扩大使用范围。

## D-007：微信销量快查日志保留 360 天

- 日期：2026-08-30
- 状态：已采用
- 背景：微信销量快查需要保留用户标识、原始商品分享内容和结果日志，以支持排障、去重和使用统计；这些记录包含需要受控管理的数据。
- 决定：每次查询完成后，相关查询日志保留 360 天；到期后删除或进行不可逆脱敏。
- 原因：该期限为市场分析和问题回溯提供跨年度的连续窗口，同时为数据最小化保留明确上限。
- 替代方案：永久保留；未采用，因为会无期限累积用户标识与原始消息。短期保留；未采用，因为会削弱跨季度排障和使用统计能力。
- 影响：后续实现必须支持按完成时间执行到期删除或不可逆脱敏，并以该期限设计日志查询和验收测试。

## D-008：微信销量快查面向所有微信客服会话用户开放

- 日期：2026-08-30
- 状态：已采用
- 背景：微信销量快查的核心体验是用户在已有微信环境中直接发送商品分享内容；需要明确 MVP 是否限于预先获准人员。
- 决定：所有进入“柳云岛销量快查”微信客服会话的用户均可发起单次商品查询，不要求预先登记或邀请。
- 原因：公开入口降低使用门槛，符合“微信发送商品分享即可取得估算”的 MVP 目标。
- 替代方案：仅开放给内部人员或受邀用户；未采用，因为会增加用户准入步骤并削弱即时查询体验。
- 影响：后续实现必须提供公开入口的防滥用保护，并在并发、日志和隐私验收中覆盖匿名或未预登记用户。

## D-009：公开查询入口按用户每日限额 10 次

- 日期：2026-08-30
- 状态：已采用
- 背景：微信销量快查面向所有微信客服会话用户开放，需要限制单个用户对 ECComment 数据服务的消耗并抑制自动化滥用。
- 决定：同一微信用户在每个自然日最多发起 10 次查询；达到限额后不再提交新的数据服务查询，并提示次日可再次使用。
- 原因：10 次足以支持正常的商品查看，同时为公开入口提供明确、可验证的资源保护边界。
- 替代方案：不设限额；未采用，因为会使公开入口容易被批量滥用。更低或更高的固定限额；未采用，因为当前没有显示其较 10 次更符合 MVP 使用场景的证据。
- 影响：后续实现必须按用户和自然日统计额度，拒绝超额查询且不调用 ECComment；验收测试必须覆盖第 11 次查询。

## D-010：微信公众号先采用同步直连 ECComment 的最小范围

- 日期：2026-08-31
- 状态：已采用；D-007 至 D-009 所属的完整方案暂缓实施
- 背景：现有 `/wechat/callback` 已完成公众号明文与 AES 安全模式收发验证，本阶段只需识别淘宝商品链接并返回 ECComment 结果。
- 决定：保留现有回调协议流程；文本包含指定淘宝或天猫域名时同步调用 ECComment，否则提示用户发送淘宝商品链接。失败统一回复安全文案并写错误日志。本阶段不增加 AI、数据库、用户系统、企业微信、配额或留存任务。
- 原因：该范围可直接复用已验证的公众号回调，依赖面和运行状态最少，符合当前明确的交付边界。
- 替代方案：立即实施带数据库、每日配额和企业微信异步消息链路的完整规格；暂不采用，因为超出本阶段需求。
- 影响：ECComment 必须在公众号被动回复时限内返回；若后续查询耗时无法满足时限，需要另行决策异步回复方式，而不能在本次范围中静默增加状态系统。

## D-011：ECComment 最小估算接口与公众号服务同进程部署

- 日期：2026-08-31
- 状态：已采用
- 背景：公众号回调客户端已经依赖 `POST /api/sales/estimate`，但 ECComment 侧尚无可调用服务；现有项目工作簿和 D-003 月销量计算已经包含所需数据与口径。
- 决定：在独立微信 FastAPI 进程内增加只读估算接口，从服务器项目工作簿建立内存目录并复用 D-003 计算；公众号客户端通过 `http://127.0.0.1:8511/api/sales/estimate` 调用，不为该路径增加 Nginx 公网路由。接口以部署环境中的独立 Bearer Token 鉴权，并在服务启动时预热工作簿目录。
- 原因：同进程回环调用保留了清晰的 HTTP 契约，同时不增加新进程、端口和公网攻击面；启动预热可避免首次读取 Excel 超出公众号被动回复时限。
- 替代方案：先建设独立 ECComment 服务或把估算逻辑直接写进回调函数；前者超出当前最小范围，后者会取消已建立的服务边界并使后续拆分更困难。
- 影响：生产微信虚拟环境必须安装 Pandas 与 OpenPyXL，并可只读访问 `/opt/tmall-comment/projects`；令牌由运维自行生成，不属于微信 Token、AppSecret 或模型供应商密钥。若未来拆分 ECComment，只需替换估算 URL 和对应服务凭据，不改变公众号回复契约。
